# Memory module — runtime agent state

> **Location:** `.sdlc/memory/` · **Git:** mixed — some files committed, some gitignored

## Purpose

Persistent **session and context** for agents across turns and IDE restarts. Not module configuration — this is **live state** written during pipeline execution.

## Memory Classes

| Class | Files | Git policy | Cleanup rule |
|-------|-------|------------|--------------|
| **Runtime local** | `session-gate.json`, `doctor-health.json` | Gitignored | Regenerated by tools; never hand-edit as evidence |
| **Runtime generated** | `discovery-context.json` | Versionable if useful to current workflow | Refresh via `workflow discover`; stale data may be replaced |
| **Active handoff** | `orchestrator-handoff.md` | Versionable during SDLC_META; avoid product-session churn | Overwritten by the latest agent handoff |
| **Operational context** | `operational-context.md`, `architecture.md`, `business-rules.md`, `incidents.md` | Versionable | Keep concise, current, and source-linked |
| **Optional planning aid** | `test-skeleton.md` | Versionable only when produced as acceptance evidence | Remove or refresh when no longer tied to active card |
| **Execution ledger** | `../manifest/executions.jsonl` | Versionable (pruned) | Append-only; post-gateway + workflow finish |
| **Execution snapshot** | `execution-RPG-N.json` | Versionable | Generated on workflow finish; replaces legacy `rpg-N-evidence.json` |

## Files

| File | Purpose | Written by | Read by |
|------|---------|------------|---------|
| `orchestrator-handoff.md` | **Routing** between subagents (Markdown) | Every subagent + `workflow classify` | **Orchestrator first** |
| `session-gate.json` | Write gate cache (`card`, `branch`, `stage`) | `gate.py` / `workflow start\|finish` | Hooks, all agents |
| `operational-context.md` | Env, services, rolling session summaries | DevOps, Orchestrator | All agents |
| `architecture.md` | Boundaries, ADR summary | Architect | Implementer, Reviewer |
| `business-rules.md` | Domain invariants | Planner | All agents |
| `incidents.md` | Production incident log | Observer, DevOps | AutoFixer, Rollback |
| `discovery-context.json` | Repo discovery snapshot | `discovery_hook.py` | Intent Analyst, Planner |
| `doctor-health.json` | Last Doctor run summary | `doctor.py` | Human, Orchestrator |
| `test-skeleton.md` | QA test stubs (requirements stage) | QA skeleton mode | Implementer, QA |

**Gitignored:** `session-gate.json` and `doctor-health.json` (local mechanical state / generated health summary).

## Ownership Rules

- `session-gate.json` is a cache, not project history. Plane remains the workboard source of truth.
- `orchestrator-handoff.md` is a routing document, not long-term evidence. Keep it short and current.
- `architecture.md` and `business-rules.md` hold durable constraints. Update them only when architecture or domain rules change.
- `operational-context.md` holds rolling summaries. Compact aggressively; do not paste long logs.
- `discovery-context.json` may be stale after large repo changes. Regenerate before planning new product work.

## Handoff format (Markdown — not YAML)

All subagents write **plain Markdown** to `orchestrator-handoff.md`. The Orchestrator parses **`Next agent`** and **`Stage complete`** to spawn the next Task.

### Required sections

Use this structure (copy and fill):

```markdown
# Orchestrator Handoff (latest)

## Routing

| Field | Value |
|-------|-------|
| **Next agent** | planner |
| **Stage complete** | yes |
| **Previous agent** | intent-analyst |

## Classification

| Field | Value |
|-------|-------|
| **Intent** | FEATURE |
| **Confidence** | 0.9 |
| **Requires Plane** | yes |
| **Requires branch** | yes |

## Session

| Field | Value |
|-------|-------|
| **Card** | RPG-N |
| **Epic** | RPG-M |
| **Branch** | feature/RPG-N-slug |
| **Stage** | implementation |

## Scope

Short prose: what this work unit covers and why.

## Acceptance criteria

- Criterion 1
- Criterion 2

## Blockers

- none

## Notes

Optional: commits, PR urls, architecture decisions, deferred items.
```

### Field conventions

| Field | Values |
|-------|--------|
| **Next agent** | `planner`, `architect`, `implementer`, `qa`, `auto-fixer`, `reviewer`, `devops`, `none` |
| **Stage complete** | `yes` / `no` |
| **Intent** | `GREENFIELD`, `FEATURE`, `BUGFIX`, `HOTFIX`, `SDLC_META`, `DOCS_ONLY`, `INFRA`, `READONLY` |
| **Requires Plane / branch** | `yes` / `no` |

### Do not

- Wrap handoff in ` ```yaml ` fences
- Omit **Next agent** — Orchestrator cannot route
- Write product handoff into `.sdlc/` during unrelated SDLC_META work (and vice versa)

## Cross-session resume (Orchestrator)

Before each turn:

1. Read `session-gate.json` — if `gate_status: open`, **continue** same card (do not re-classify)
2. Read `orchestrator-handoff.md` — apply **Next agent**
3. Read last block in `operational-context.md` only (not full history)
4. Read `discovery-context.json` for repo snapshot

## Rolling-summary protocol

When approaching context limit:

1. Pause before next action
2. Append compact summary to `operational-context.md`:

```markdown
## Session summary — 2026-06-01T12:00:00Z
- **Stage:** implementation
- **Card:** RPG-N
- **Branch:** feature/RPG-N-slug
- **Completed:** …
- **In progress:** …
- **Next:** …
```

3. Drop stale tool output from context; continue from summary + key files

```bash
make sdlc-compact-memory
```

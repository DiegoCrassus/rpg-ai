# Product Vision

## One-liner

A web platform for RPG groups to store, organize, and share campaign information in a secure, modular, per-campaign sandbox.

## Problem

RPG campaigns generate scattered information: character sheets, lore, NPCs, session notes, secrets, and rules. Generic note apps lack **narrative visibility control** — the core RPG constraint that not every player knows everything.

## Solution

Each **Mesa** (campaign) is an isolated universe with its own:

- Rules and RPG system label
- Custom character sheet templates
- Documents and lore
- Participants and per-Mesa roles
- Visibility rules per resource

## What we are

- **Campaign information repository** — organized, searchable, permission-aware
- **Per-campaign sandbox** — no shared assumptions about sheet layout or rules
- **Narrative access control** — Master vs Player knowledge is first-class

## What we are not (initially)

| Non-goal | Notes |
|----------|-------|
| Virtual tabletop | No maps, tokens, or tactical combat |
| Dice roller | Out of MVP |
| Real-time chat | Out of MVP |
| Rules automation | Out of MVP |
| AI narrative assistant | Future phase |
| Template marketplace | Future phase |

## Differentiation

The product is not "Google Docs for RPG." The differentiator is **Mesa isolation + narrative permissions**:

- Custom sheet schemas per campaign
- Document visibility down to a single player or character
- Clear separation between Master knowledge and Player knowledge
- Campaign-specific organization without forcing a single RPG system

## Target users

| User | Need |
|------|------|
| **Master** | Centralize lore, control secrets, manage players and sheets |
| **Player** | Own character sheet and story; see only what the Master allows |
| **Admin** | Platform operations — not a narrative role |

## Success criteria (MVP validation)

1. A Master can run a full campaign loop: create Mesa → invite Players → define sheet template → create documents with mixed visibility → Players see only permitted content.
2. Two Mesas on the same platform share zero data.
3. A Player in Mesa A as Master and Mesa B as Player experiences correct role separation.

## Product name

**RPG Platform** (Q-001, 2026-06-11) — working title for MVP. Commercial branding and domain decided pre-launch.
